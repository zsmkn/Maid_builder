# Maid Builder 玩法擴充計畫：領地與建設

> 在現有的「藍圖 → BuildJob → 建築師女僕」流程上加一層遊戲性：放置領地旗幟，在領地內用建造模式挑選建築模板，女僕蓋好後建築註冊到領地、累積繁榮度，繳交材料升級領地，解鎖更多模板與加成。
> 基礎系統的決策與進度見 [plan.md](plan.md)。本文件只寫玩法層。

---

## 0. 已確定的決策

| 項目 | 決定 |
|---|---|
| 觀察者／RTS 視角 | **取消**。建造模式使用一般第一人稱視角。 |
| 生產建築 | 建築本身**不自動產出**，玩家可以自己去砍樹、種田。女僕指派到建築工作是**方便功能**（§2.5），**不列入繁榮度判斷**。 |
| 伐木任務 | 不寫（TLM 沒有伐木任務，伐木場只是模板建築）。 |
| 繁榮度來源 | 完整的模板建築＋領地內處於**家模式**的女僕數（§1.2）。 |
| 升級 | 繁榮度門檻＋指定建築＋**繳交升級材料**。 |
| 旗幟數量 | 每位玩家最多 **10 支**（設定可調）；任兩支旗幟（不分玩家）之間至少相距 **10 個區塊**；各領地的等級與繁榮度**分開計算**。 |
| 領地範圍 | 以旗幟為中心的正方形，**隨等級擴大**（升級的一部分，不算加成）。每級半徑由等級表定義，Lv1 預設 48 格；最大半徑必須小於旗幟間距的一半（< 80 格），所以領地永遠不會重疊，升級擴大時也不用檢查衝突。載入等級表時驗證，超過就截到上限並在 log 警告。 |
| 加成 | 只做：領地內不生成敵對生物、女僕在領地內緩慢回血、溫室作物生長加速、牧場動物繁殖冷卻縮短。**不做**建造速度、鷹架、同時工作數、範圍類加成。 |
| 建築完整度 | ≥ **80%** 算運作中，**忽略裝飾方塊**。 |
| 拆旗幟 | 領地失去功能（建築、加成全部停止），資料保留；擁有者在原位附近重新放旗幟即可接手。 |
| 多人共享領地 | 先保留 `members` 資料欄位，不做介面。 |
| 倉庫 | 倉庫是**模板建築**，用來存放女僕工作的產物（§2.5），**不是**領地材料箱。領地材料箱另外綁定（§1.2-3）。 |
| 模板美術 | 由 `tools/TemplateGenerator.java` 產生（2026-10-13 重做，見 plan_done.md §9）；開發者之後可用自己的 `.litematic` 覆蓋同名檔。 |
| 建造模式按鍵 | 預設 Caps Lock，可在控制設定中修改。 |
| 延後 | 建築升級（`upgrade_from`）、整地選項：都依賴「拆除方塊」。拆除已在 plan.md Phase 7 第七批實作（`BlockBreaker`、`BuildPhase.CLEAR`、`ClearMode`），可以在此基礎上設計。 |

## 1. 玩法

### 1.1 核心循環

```
放旗幟（Lv1）
  → 建造模式選模板（只有基礎模板）→ 放置 → 女僕依佇列自動蓋
  → 完工的建築註冊到領地，安排女僕在領地內住下（家模式）→ 繁榮度增加
  → 繁榮度＋指定建築達成 → 在旗幟繳交升級材料 → 領地升級
  → 範圍擴大，解鎖進階模板與加成 → 重複
```

### 1.2 機制

1. **繁榮度（Prosperity）**＝建築分＋居民分
   - 建築分：每個「運作中」的模板建築提供的分數（模板定義）。
   - 居民分：領地內的居民女僕數 × 每位分數（等級表定義，可設上限，避免靠大量女僕刷分）。居民女僕＝擁有者是領地擁有者、開啟家模式、家模式工作點在領地範圍內。
   - 計算時機：女僕所在區塊不一定已載入，所以居民數用 TLM 的 `MaidTickEvent` 低頻（每 200 tick）回報到領地，記錄「女僕 UUID → 最後回報時間」，超過一段時間沒回報（例如 10 分鐘）才移除。玩家站在旗幟旁時領地內的區塊都已載入，數字是準的。
2. **建築完整度**：註冊的建築定期比對世界與模板，非裝飾方塊 ≥ 80% 正確才算運作中。被破壞時暫停（繁榮度不計、加成停止），旗幟介面顯示「需修復」，一鍵建立修復工作——**修復＝同一個放置位置再建一次 BuildJob**，已經放好的方塊自動跳過。
   - 裝飾方塊用 block tag `maidbuilder:integrity_ignored`（資料包可改）：花、盆栽、地毯、火把、燈籠、告示牌、旗幟、按鈕、壓力板、蠟燭等。
3. **領地材料箱**：材料箱可以綁在**領地**上（在旗幟介面進入綁定模式，或手持旗幟介面給的工具右鍵容器），領地內所有工作共用；個別工作仍可以另外綁材料箱。
4. **建造佇列**：領地內可以同時排多個建築，旗幟介面可以調整順序。指派給領地的建築師女僕依序挑工作，不用每次都拿魔杖綁定。
5. **自訂藍圖**：建造模式裡另有「自訂」分類，列出玩家自己的 `schematics/`，可以蓋，但不註冊為建築、不提供繁榮度。
6. **升級材料**：由等級表定義，可以要求 TLM 道具（例如御幣、蛋糕），讓玩法和女僕本體連結。從玩家背包＋領地材料箱扣除。

### 1.3 等級表（範例，數值之後調整）

| 等級 | 半徑 | 繁榮度 | 指定建築 | 升級材料（舉例） | 解鎖 |
|---|---|---|---|---|---|
| 1 | 48 | — | — | — | 倉庫、甘蔗田、小溫室、伐木場 |
| 2 | 56 | 30 | 倉庫 | 原木 ×64、鐵錠 ×16 | 牧場、養蜂場、居民宿舍；**女僕回血** |
| 3 | 64 | 80 | 溫室、牧場 | 金錠 ×16、蛋糕 ×4 | 大溫室、大牧場；**溫室加速**、**牧場繁殖** |
| 4 | 72 | 160 | 3 種以上生產建築 | 鑽石 ×8、御幣 ×1 | 進階模板；**不生成敵對生物** |
| 5 | 79 | 300 | … | … | 裝飾性高級模板 |

### 1.4 加成

| 加成 | 範圍 | 實作方向（實作前在 NeoForge 原始碼確認事件名稱） |
|---|---|---|
| 不生成敵對生物 | 整個領地 | 生成檢查事件（`MobSpawnEvent` 系列）中，`MobCategory.MONSTER` 且位置在領地內則拒絕；刷怪籠生成不擋（設定可改） |
| 女僕緩慢回血 | 整個領地 | `MaidTickEvent`，每 100 tick 回 1 點 |
| 作物生長加速 | 運作中的溫室範圍內 | 作物生長事件後，機率額外推進一次生長 |
| 繁殖冷卻縮短 | 運作中的牧場範圍內 | 動物繁殖事件後，縮短雙親的冷卻時間 |

- 全部可在伺服器設定中個別關閉。
- 「位置在哪個領地」的查詢會在生成檢查這類高頻事件中呼叫：用「區塊座標 → 領地」的索引，查詢 O(1)；建築範圍查詢也先用區塊過濾。

### 1.5 不做

- 領地保護／圈地（交給 FTB Chunks、Open Parties and Claims 等）。
- 建築自動產出物品。
- RTS 觀察者視角。

## 2. 系統設計

### 2.1 資料模型

```
TerritoryData (SavedData，每個維度一份)
└─ Territory
   ├─ id, owner(UUID), members(Set<UUID>)        # members 只保留欄位
   ├─ flagPos, level, active                     # active=false：旗幟已拆，等待接手
   ├─ materialSources (Set<GlobalPos>)           # 領地材料箱
   ├─ jobQueue (List<jobId>)                     # 依優先順序
   ├─ residents (Map<UUID, lastSeenTick>)        # 居民女僕
   └─ buildings (List<RegisteredBuilding>)
      ├─ templateId, placement（原點／旋轉／鏡像）, bounds
      ├─ state: ACTIVE / DAMAGED
      ├─ integrity（最近一次檢查結果）
      └─ assignedMaids (Set<UUID>)

TemplateDef（資料包：data/<ns>/maidbuilder/templates/<id>.json）
├─ structure: "maidbuilder:templates/lumberyard_1"   # .litematic 或 .nbt，放在 mod resources
├─ category: production | storage | housing | decoration
├─ required_level, prosperity
├─ bonus: none | greenhouse | ranch                  # 範圍型加成
├─ storage: true/false                               # 是否為倉庫
├─ workplace: {                                      # 選用
│    task: "touhou_little_maid:feed_animal", max_maids: 2,
│    products: ["minecraft:beef", "#c:leathers", ...] }   # 「存放倉庫」只存這些（物品 ID 或 tag）
└─ icon、名稱與說明的翻譯鍵

territory_levels.json（資料包）
└─ 每級：radius, prosperity, required_buildings, upgrade_items, resident_points, resident_cap, unlocks, bonuses
```

- 純邏輯放 `core/`（不碰 MC，JUnit 測試）：等級表與升級條件判定、繁榮度計算、模板解鎖判定、旗幟間距與數量判定、完整度比例計算。
- 內建模板結構檔放 `data/maidbuilder/maidbuilder/templates/*.litematic`，用 `SchematicReader` 讀（已支援依內容判斷格式）。

### 2.2 旗幟放置與接手

- 放置檢查：該玩家已有旗幟數 < 上限；與任何現有旗幟（含未啟用的）距離 ≥ 10 區塊。不符合時放不下並顯示原因。
- 拆旗幟：`active=false`，建築、加成、佇列全部暫停（工作中的女僕停工並收鷹架，同取消流程但不刪除工作），資料保留。
- 接手：擁有者在未啟用領地的原旗幟位置附近（領地範圍內）放新旗幟 → 恢復該領地，旗幟位置更新，不佔新的旗幟名額。
- 其他玩家不能在未啟用的領地範圍內放旗幟（避免搶地）；管理員可用指令刪除。

### 2.3 與現有系統的接點

| 現有 | 擴充 |
|---|---|
| `BuildJob` | 新增選用欄位 `territoryId`、`templateId`；完工時通知領地註冊建築 |
| `BuildJobFactory` | 新增「從內建模板建立」（讀 mod resources，而不是 `schematics/`） |
| `MaterialReports` | 材料來源加入領地材料箱；可以一次統計佇列中所有工作 |
| `BuilderFindTargetTask` | 女僕綁定領地時，從 `jobQueue` 依序挑工作 |
| `GhostPreview` / `PreviewManager` | 建造模式直接重用；新增「放置無效」的整體泛紅（超出領地、與其他建築重疊、等級不夠） |
| `MaterialListScreen` | 內容嵌進旗幟介面的「建設」分頁 |

### 2.4 旗幟介面（右鍵旗幟）

分頁：
1. **概況**：等級、繁榮度（建築分＋居民分分開顯示）、下一級條件（✔／✘ 逐條列出）、升級材料（擁有／需要，同材料清單的三色顯示）、升級按鈕。
2. **建設**：佇列中的工作（進度、參與女僕、缺料數），可調整順序、取消；展開單一工作的材料清單；「建造模式」按鈕；領地材料箱管理。
3. **建築**：已註冊建築、狀態（運作中／需修復）、完整度百分比、指派的女僕；「修復」按鈕。
4. **女僕**：居民女僕列表——目前任務、是否在家模式、**背包狀態**（已用格數／總格數，滿了標紅），以及「存放倉庫」按鈕（§2.5）。

### 2.5 女僕指派到建築（方便功能，不影響繁榮度）

- 在「建築」或「女僕」分頁把女僕指派到有 `workplace` 的建築：女僕的 TLM 任務切換成模板定義的任務，家模式工作點設在建築中心。
- 可對應的 TLM 任務：`TaskNormalFarm`（溫室）、`TaskFeedAnimal` / `TaskShears` / `TaskMilk`（牧場）、`TaskHoney`（養蜂場）、`TaskFishing`（漁場）、`TaskSugarCane` / `TaskMelon`。實際任務 ID 以 `refs/TouhouLittleMaid-1.21` 為準。
- **背包滿了**：女僕自動切換成休閒任務（`TaskIdle`）停止工作，並記住原本的任務；女僕介面標示「背包已滿」。
- **處理方式**：
  - 玩家自己去找女僕拿東西。
  - 介面按「存放倉庫」：女僕走到領地內**運作中的倉庫**，只把模板 `workplace.products` 列出的產物放進倉庫內的容器（工具、建造材料和其他物品都留在身上）。沒有倉庫時按鈕停用並提示「需要先建造倉庫」；倉庫容器也滿了時停止存放並在介面提示。
- **自動恢復工作**：休閒中的女僕每 40 tick 檢查一次，背包空格達到 50%（設定可調）就自動切回原任務。玩家在這段期間手動改了她的任務時，以玩家的為準，不再自動切回。
- 倉庫的容器＝倉庫建築範圍內所有提供 ItemHandler 的容器，完工時自動登記。

### 2.6 建造模式

- 進入：站在自己的領地內按建造鍵（預設 Caps Lock，可改），或在旗幟介面按「建造模式」。
- 模板目錄畫面：依分類分頁；未解鎖的模板顯示鎖頭與條件；滑鼠移上去顯示尺寸、材料總量、繁榮度、加成與可指派的任務。
- 放置：選好模板後使用現有的魔杖預覽操作（`R` 旋轉、`M` 鏡像、方向鍵／PgUp/PgDn 微調），預設把模板底部貼在指著的地面上；確認後建立 BuildJob 並排入領地佇列。
- 無效放置（超出領地、與其他已註冊建築或佇列中的建築重疊、等級不夠）時預覽泛紅，不能確認。

## 3. 開發階段

> 每個階段一個 branch（`gameplay/g0-territory` 等），完成驗收再合併。

### G0 — 領地旗幟
- `ModBlocks` / `ModBlockEntities`（本模組第一個方塊）、旗幟方塊、合成配方。
- `TerritoryData`：建立、拆除後停用、接手、數量上限與 10 區塊間距、區塊索引。
- 邊界顯示：手持旗幟或站在領地內按鍵時畫範圍線（重用預覽的框線渲染）。
- 旗幟介面「概況」分頁（等級、範圍）。
- ✅ GameTest：第 11 支旗幟放不下；兩支旗幟相距不到 10 區塊時放不下；重啟後領地仍在；拆旗幟後停用、原地附近重放可接手且不佔新名額；其他玩家不能在停用領地內放旗幟。

### G1 — 模板與建造模式
- `TemplateDef` 資料包載入（`AddReloadListenerEvent`），同步到客戶端。
- 先用暫代模板（倉庫、甘蔗田、小溫室、伐木場），正式 `.litematic` 由開發者提供後替換。
- 建造鍵、模板目錄畫面、重用 `PreviewManager` 放置、貼地、無效放置判定。
- BuildJob 加上 `territoryId` / `templateId`；領地佇列；領地材料箱。
- 旗幟介面「建設」分頁＋材料清單。
- ✅ 在領地內選模板放置，女僕依佇列蓋完；材料清單的數字和女僕實際拿的一致；超出領地或重疊時不能放。

### G2 — 建築註冊、繁榮度、升級
- 完工 → `RegisteredBuilding`；完整度檢查（分批比對，每 tick 有上限，只檢查已載入區塊；忽略 `integrity_ignored`）。
- 居民女僕回報（`MaidTickEvent`）。
- 繁榮度、等級表、升級條件、繳交材料、模板解鎖。
- 旗幟介面「建築」「女僕」分頁（女僕分頁先只顯示列表與背包狀態）、修復按鈕。
- ✅ GameTest：完工後建築分增加；家模式女僕使居民分增加、關閉家模式後移除；挖掉 25% 非裝飾方塊後變成需修復、拿掉花不影響；修復後恢復；條件達成且材料足夠時可升級，材料被扣除，半徑擴大，新模板解鎖。

### G3 — 加成
- 不生成敵對生物、女僕回血、溫室生長加速、牧場繁殖冷卻（§1.4），各自可在設定中關閉。
- ✅ GameTest：領地內（達到等級時）不生成敵對生物、領地外照常；建築需修復時溫室／牧場加成停止；女僕回血只在領地內。

### G4 — 女僕指派與倉庫存放
- 指派女僕到建築、切換 TLM 任務與工作點。
- 背包滿 → 切換休閒任務、記住原任務；空格達 50% 自動恢復。
- 「存放倉庫」：走到倉庫，只存放 `products` 列出的產物。
- ✅ 溫室女僕會自己耕作；背包塞滿時停止工作並在介面顯示；按「存放倉庫」後產物進到倉庫容器、女僕回去工作；沒有倉庫時按鈕停用。

### 1.2.0 服務建築（2026-10-28）
驛站（流浪商人、驛站間傳送）、村民集會所、瞭望塔、食堂、神社，分類 `service`，Lv5 需 2 種。細節見 plan_done.md §12。原本「建築自動產出物品」不做的原則不變：商人與村民是來訪／入住的生物，不是產出物品。

### 延後
- 建築升級（`upgrade_from`）、整地選項：拆除方塊已完成（plan.md 第七批），之後在其上實作。
- 多人共享領地介面。

### 實作紀錄（與上面設計不同或新增的地方）

- **第二輪調整（使用者回饋）**：
  - 建築師不再分「領地建築師」：任務是建築師、且沒有自己未完成工作的女僕，會自動依序建造她所屬領地（家模式工作點所在，沒開家模式則是所在位置）的佇列；先把手上工作（含鷹架拆除）做完才換下一個。「建築師」按鈕＝切換為建築師任務（再按一次改為休閒）。
  - 「工作地點…」改為開啟選單，列出領地內所有可工作的建築（任務、運作狀態、人數），滿員或需修復的不能選，另有「不在建築工作」。
  - 自動偵測：女僕任務與某建築的工作任務相同、且家模式工作點（沒開家模式則是她的位置）在建築範圍內（外加 2 格），就自動登記為在該建築工作（有空位時）；之後改成別的任務或把工作點搬離建築，就自動取消登記；女僕死亡也會釋出名額。

- **旗幟**：沒有 BlockEntity，領地以旗幟位置查詢。旗幟間距以「旗幟座標的 x 或 z 距離 ≥ 間距 × 16 格」計算；最大半徑自動限制為 `(間距×16 − 1) / 2`（預設 79），所以任何等級的領地都不會重疊，其他玩家也就不可能在停用領地內放旗幟。旗幟上限計算「擁有的領地數」（含停用的）；`/maidbuilder territory remove` 可釋出名額。
- **模板不可蓋住旗幟**（實機截圖發現）：伺服器與客戶端都檢查，預覽泛紅並顯示原因。
- **泛紅預覽**：顏色乘在頂點上（`AlphaVertexConsumer`），原版只對可染色面套用模型顏色。
- **建造模式**：模板跟隨準星（最遠 48 格），足跡中心對準看著的方塊；左鍵或建造鍵離開；`B` 開材料清單（建造模式的預覽）。
- **自訂藍圖**：目錄有「自訂」分頁說明；在自己領地內用藍圖魔杖確認的工作會自動加入領地佇列（使用領地材料箱），完工後只離開佇列、不刪除工作也不登記建築。
- **領地材料箱**：用「綁定材料箱」模式（右鍵容器切換，潛行＋右鍵或再按按鈕結束，2 分鐘沒動作自動結束）；容器必須在領地內。女僕取料、材料清單、HUD 都會一併計算工作本身與領地的材料箱。
- **完整度**：裝飾方塊標籤 `maidbuilder:integrity_ignored`（花、地毯、火把、燈籠、告示牌、旗幟、按鈕、壓力板、蠟燭、樹苗、作物、甘蔗…）；空氣與流體不計；泥土、草、耕地、土徑互相視為正確（田會被鋤、路會被踩）。另外新增「取消登記」（✕ 按兩次），方塊不拆除，空出位置。
- **材料換算修正**：耕地、土徑改為需要泥土（原本會要求生存模式拿不到的耕地物品）。
- **居民**：每位女僕每 100 tick 回報一次「家模式工作點所在的領地」；10 分鐘沒回報才移除（區塊未載入時仍計入）。
- **升級物品**：可用 `#標籤`；從玩家背包優先扣，不足再從領地材料箱扣。
- **女僕回血**：TLM 女僕本身就會隨機緩慢回血（約每 400 tick 半顆心），加成是額外每 100 tick（可調）半顆心。
- **存放倉庫**：新增隱藏的 TLM 任務 `maidbuilder:deposit`；女僕依序走到最近、有空位的倉庫容器，存完（或所有容器滿了、60 秒走不到）就回到原本的任務。途中暫時借用她的家模式工作／閒置／睡覺點，讓 TLM 不會把她拉回或傳送回工作點，結束後還原。存放時每種產物保留模板 `keep` 個（溫室保留 16 個，用來補種）。
- **暫代模板**：11 個簡單造型（`data/maidbuilder/maidbuilder/structures/*.litematic`，由腳本產生），之後換成正式的 `.litematic` 只需覆蓋同名檔案（或改模板 JSON 的 `structure`）。
- **自測**：`runClientSelfTest` 另外輸出 `maidbuilder_selftest_territory_*.png`（概況、建設、建築、女僕、目錄、建造模式正確／泛紅），結束後清除旗幟、建築與女僕。

## 5. 交接注意事項

### 尚未驗證
- **實機手感**：建造模式（準星跟隨、高度微調、右鍵排入）、領地介面各分頁、工作地點選單都只經過自測截圖與 GameTest，還沒有真人實際遊玩過。
- **Caps Lock 與輸入法**：預設建造鍵是 Caps Lock，注音／新注音等輸入法可能會攔截或切換大小寫，請實測；有衝突就把 `TerritoryKeys.BUILD_MODE` 的預設鍵改掉。
- **專用伺服器**：領地清單同步、模板結構下載（`TemplateStructure` 單包上限 1 MiB，模板檔超過 1000 KiB 會被拒絕載入）、多玩家同時開領地介面，都只在單人／GameTest 環境跑過。
- **TLM 其他工作任務**：只有農夫任務（`touhou_little_maid:farm`）有 GameTest；牧場（餵食動物）、養蜂、釣魚、甘蔗的實際產物是否都被 `products` 涵蓋、背包滿時的行為，需要實機確認並視需要調整模板 JSON。

### 內容待補
- **模板美術**：11 個內建模板由 `tools/TemplateGenerator.java` 產生（plan_done.md §9），可直接改腳本重產，或用正式 `.litematic` 覆蓋。換成正式 `.litematic` 時覆蓋 `neoforge/src/main/resources/data/maidbuilder/maidbuilder/structures/` 下的同名檔即可；若尺寸變大，注意建築不能蓋住旗幟、不能超出領地，Lv1 半徑 48 格。
- **數值平衡**：等級表（`data/maidbuilder/maidbuilder/territory_levels/level_*.json`）、各模板的繁榮度與 `max_maids`、加成數值（伺服器設定 `territory.bonuses`）都是暫定值。
- **貼圖**：領地旗幟沿用原版材質（木頭、金塊、紅／白羊毛）組成的方塊模型，沒有專用貼圖。

### 程式結構速查
- 伺服器端：`common/territory/`（資料 `Territory` / `TerritoryData`、規則 `TerritoryManager`、模板 `TemplateRegistry` / `TemplatePlacement`、完整度 `BuildingIntegrity`、加成 `TerritoryBonuses`、升級與修復 `TerritoryUpgrades`、女僕工作 `WorkplaceActions`、介面資料 `TerritoryReports` / `TerritoryActions`、同步 `TerritorySync`）；不碰 MC 的規則在 `core/territory/`（有 JUnit）。

- 客戶端：`client/territory/`（`TerritoryScreen`、`TemplateCatalogScreen`、`WorkplacePickerScreen`、`BuildMode` + `BuildModeHud`、`TerritoryBorderRenderer`）；建造模式的預覽沿用 `PreviewManager` / `GhostPreview`（檔名以 `template:` 開頭的放置）。

### 已知限制
- 領地沒有高度限制（整個柱狀範圍），邊界線只是在玩家附近畫一圈示意。
- 不做領地保護／圈地，其他玩家仍可破壞領地內方塊或旗幟（拆旗幟只會讓領地停用）。
- `members` 欄位已保留但沒有介面，目前只有擁有者（與 OP）能管理領地。
- 建築升級（`upgrade_from`）與整地選項延後；所需的「拆除方塊」已完成（plan.md 第七批）。
- 自訂藍圖（藍圖魔杖放在自己領地內的工作）會進領地佇列，但不登記為建築、不計繁榮度。
- `maidsHealAtLevel` 測試依賴 TLM 的隨機回血不超過門檻，理論上約有 0.1% 機率誤判失敗，重跑即可。
- 我在這階段順手改了一個原有行為：`MaterialRules.hasItemOverride`，耕地、土徑的材料改為泥土（原本會要求拿不到的耕地物品），會影響藍圖魔杖的材料清單。
