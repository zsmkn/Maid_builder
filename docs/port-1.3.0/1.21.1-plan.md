# 女僕建造模組（Maid Builder）開發計畫

> 讓東方女僕（Touhou Little Maid）依照玩家放置的建築投影，自動搬材料、自動建造。
> 本檔只放**現況摘要、待辦與交接事項**。已完成功能的設計理由、實作細節、測試名稱見 [plan_done.md](plan_done.md)（需要時再讀）；領地玩法見 [plan_gameplay.md](plan_gameplay.md)。

## 基本決策

- MC **1.21.1**、NeoForge 21.1.x（需求 21.1.219+）、Java 21、ModDevGradle；唯一硬依賴 TLM 1.5.3+（Modrinth maven）。
- 不依賴 Litematica；讀 `.litematic` 與原版 `.nbt`。Litematica／Forgematica／Structurize 只參考不複製（LGPL）；TLM 為 CC-BY-NC-SA → 本模組不可商業化。
- `core/`（純 Java、JUnit）放不碰 MC 的邏輯：NBT、藍圖讀寫、旋轉鏡像、建造順序（`BuildPlanner`）、材料規則、領地規則。`neoforge/` 放其餘；`client/` 越薄越好（渲染只畫半透明 BlockState，未來移植最脆弱）。

## 版本與 tag

- 平常照功能 commit，不必以版本為單位；要發版時在當下的 commit 打 annotated tag：`git tag -a v1.1.0 -m "Maid Builder 1.1.0"`，再 `git push origin v1.1.0`（或 `git push --tags`）。
- tag 名稱與 `mod_version` 一致（`v` + 版本號）；先改 `mod_version`、changelog 並 commit，再打 tag。
- 補標舊版本：`git tag -a v1.0.0 292e740 -m "Maid Builder 1.0.0"`。
- 兩個版本間的變更：`git log v1.0.0..v1.1.0 --oneline`（可用來寫 changelog）。

## 踩坑速查（細節見 plan_done.md §7）

- TLM 擴充：`@LittleMaidExtension` + `ILittleMaid.addMaidTask`；背包 `maid.getAvailableInv(false)`；家模式要先 `getSchedulePos().setHomeModeEnable(maid, pos)` 再 `setHomeModeEnable(true)`，否則女僕被傳到 (0,0,0)。
- TLM 尋路不會走出工作範圍（`MaidWorkRange`），大型建築由 `BuilderRangeHandler` 處理。
- serverbound payload 上限 32767 bytes（上傳每段 30000）。
- 幽靈預覽：`AFTER_TRANSLUCENT_BLOCKS` + `RenderType.translucent()`，PoseStack 為 null；光影時 `AFTER_LEVEL` 要自己推入相機旋轉。
- GameTest：template 第 0 層在 helper 相對 y=1。
- 工作進度以「步驟索引」存檔：任何會改變規劃結果的改動，都要讓舊存檔產生相同的步驟（例如新選項預設關閉），否則進度會被重置。
